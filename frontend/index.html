Install and connect Browspark
  1. 01

    Run the setup script

    For Chrome and Brave, one command downloads the extension to ~/browspark-extension, lets you pick bun, pnpm or npm, and registers the companion with the agents you choose. Add --test for a dry run that changes nothing.

    Terminal
    curl -fsSL https://browspark.krishm.dev/setup.sh | bash

    Prefer to do it by hand? Download browspark-extension.zip from the latest release, unzip it, and add the client config above yourself. Or build from source:

    Build from source
    git clone https://github.com/outofmemry/browspark.git
cd browspark
bun install && bun run build
  2. 02

    Load the Chromium extension

    Open chrome://extensions or brave://extensions, turn on Developer mode, choose Load unpacked and select ~/browspark-extension (or dist/chromium-extension/ in your clone). Repeat for each browser profile.

  3. 03

    Share. You're ready.

    Open each Browspark dashboard and share the tabs your agent may use. All profiles connect to the same companion. Ask your agent to run browser_status and choose the browser or tab you want.

Using Firefox 153+ or compatible Zen? Build from source above, open about:debugging → Load Temporary Add-on → dist/firefox-extension/manifest.json. Use the companion from that checkout, enable Firefox automation in the dashboard, and share existing tabs. The unsigned extension must be loaded again after restarting the browser. What is Browspark?

Browspark is a free, open-source browser MCP server for Chrome, Brave, Firefox and Zen, published under the MIT license. It uses the Model Context Protocol (MCP) to give AI agents 43 tools for browser automation and debugging: 22 browser tools and 21 developer tools. The server runs locally and is published on npm as browspark-mcp.

How does MCP for browser automation work?

A browser MCP server exposes browser actions as tools that an AI client can call through the Model Context Protocol. Browspark connects that client to Chrome, Brave, Firefox and Zen through a local server and the matching extension, or to separate developer sessions. Your agent can navigate, click, fill forms, read pages, and capture screenshots.

Which AI clients can use Browspark?

Browspark includes setup instructions for Claude Code, Codex, Cursor, OpenCode, Antigravity, and Muse Code. It supports MCP connections over stdio and local Streamable HTTP. Follow the MCP client connection guide to configure your agent.

Can it use my existing browser sessions?

Yes. Extension mode works in existing Chrome, Brave, Firefox and Zen tabs, including signed-in sessions. Firefox and Zen use a separate extension build with narrower automation support. Share tabs independently in each browser profile.

Can I use several browsers and agents at once?

Yes. Connect multiple MCP agents and Chrome, Brave, Firefox or Zen extension profiles, or run named developer sessions together. The dashboard's Graph page shows their connections with logos on a draggable canvas. Each tab has a unique ID. Choose a browser ID or named context when opening a new tab if more than one is available. See Using multiple browsers.

Which logos does the graph recognize?

Claude, Codex, Cursor, OpenCode, Antigravity and Muse Code; Chrome, Chromium, Edge, Brave, Helium, Vivaldi, Arc, Dia, Firefox, Tor and Zen. Other clients use an Other agent robot icon. Unrecognized browsers use Unknown Chromium or Unknown Firefox with the corresponding logo. Hover over a node in the dashboard to see its reported name. Logo recognition does not change a browser's automation capabilities; check the browser support guide.

What can my agent access?

In extension mode, each browser profile controls its shared tabs and enabled tools. You can share all supported tabs or stop access in that profile. Tabs created by the agent are shared automatically. Page content accessed by your agent may be processed by your chosen AI provider.

When do I need developer mode?

Most browsing and inspection works through the extension. For capabilities Chrome restricts for extensions—such as Lighthouse, heap snapshots, and raw protocol commands—your agent can launch a separate Chrome or Brave instance in developer mode.

Does it support Firefox and Zen?

Yes. The Firefox extension shares existing tabs on Firefox 153+ and compatible Zen builds. It supports page reading and simulated interaction, with explicit errors for unavailable native debugging, network capture and other operations. Separate developer sessions use WebDriver BiDi for broader automation support. Raw CDP and Lighthouse require Chromium. See Firefox and Zen setup and coverage.

Does it work on every page?

Browspark works on supported website tabs. Browsers restrict extension automation on internal pages, other extension pages and protected add-on stores. Firefox extension mode supports HTTP and HTTPS pages, not local files. Supported New Tab pages can be shared for navigation to a website.
